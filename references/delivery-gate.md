# 交付证据与辅助诊断

资源脚本检查材料和用量，不替代独立验收。
`guard.py` 的退出码不能证明角色、上下文隔离或业务完成。

## 完成需要什么

- standard/release：明确的交付版本、约定范围、可复查证据和独立验收结论。
- direct：可验证的产物与自检结果，明确标注“未独立验收”。
- 运行进程结束、存在 commit、回执字段齐全，都不能单独证明验收通过。

已有任务记录可以保存交付版本、验收员 ID 和证据位置。
不要为凑齐文件数量补造规格、验收员或回执。

## 如何使用现有 guard

```bash
python3 <本SKILL所在目录>/scripts/guard.py --root .
```

把输出当作排查线索，再核对实际原因。
文件、工作树、会话数量及未提交时长，只能提示成本或现场混乱。
它们不能解释工程是否完成，更不能决定谁是工程师或验收员。
脚本存在的阈值不构成自动删除、归档、换人或重复验收的授权。

发现材料与实际结果矛盾时，保留现场并修正记录。
存在真实缺陷时，交回原工程师上下文处理。
不要为了脚本变绿而丢失证据，也不要用“材料齐全”覆盖独立验收 FAIL。

先前未经排除分支、工作树副本与重复统计的数字，不作为本协议的事实依据。
具体运行身份与终态按 `runtime-evidence.md` 和 `observer-runtime.md` 核对。
