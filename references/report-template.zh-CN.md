# 汇报模板：一页纸 + 中途汇报

[English](report-template.md) | [中文](report-template.zh-CN.md)

> 规则：结论先行，证据用路径指代，不贴长日志。老板读一页就能决定接受、返工或停止。协议见 [`../PROTOCOL.md`](../PROTOCOL.zh-CN.md)。

---

## A. 完工一页纸

> **每一段都配一句人话（硬要求）。** 本模板的每一节（A1–A6）在技术内容之后，都要另起一行写 `【人话】`。
> 可复制写法：
>
> ```text
> ### <技术段>
> - <事实、命令、退出码>
>   【人话】<≤2 句，能单独读懂，能独立支撑拍板>
> ```
>
> **三条判据（缺一不算合格）**：
>
> 1. **短**：不超过两句话（≤2 句）。
> 2. **能单独读懂**：不依赖上一段的技术细节，只看这一句也能明白发生了什么。
> 3. **能支撑拍板**：老板只读这一句，也敢说「行」或「不行」。
>
> 人话层**不需要穷尽解释，也不需要术语表**：老板看不明白会直接追问。先给一句能判定的白话，比再写一篇注释更有用。

# <TASK-ID> 完工汇报

**结论**：`PASS` / `FAIL` / `BLOCKED`（以独立验收结论为准，不以工程师自评代替）

## B. 中途汇报

> 触发：阶段完成、遇到阻塞、首次失败、范围变化、上下文接近交接阈值。每次不超过半页。
> **每个要点同样配一句 `【人话】`**，写法与三条判据同 A（≤2 句 / 能单独读懂 / 能支撑拍板）。

# <TASK-ID> 中途汇报 @ <阶段/时间>

**状态**：`进行中` / `阻塞` / `需要决策`

- **已完成**：<最多 3 条，带证据路径>
  【人话】<现在到哪一步了、老板要不要做什么，≤2 句>
- **正在做**：<当前动作与预期完成条件>
  【人话】<还剩什么、大概什么时候有结果，≤2 句>
- **下一步**：<紧接着的 1–2 个动作>
  【人话】<接下来会先发生什么、需不需要老板点头，≤2 句>
- **阻塞/风险**：<事实 + 影响 + 需要谁做什么；没有就写「无」>
  【人话】<卡在哪、谁要给个决定，≤2 句>
- **范围变化**：<有/无；有则说明并等待 PM 确认>
  【人话】<活变多了还是变少了、要不要老板重新拍板，≤2 句>
- **上下文/交接**：<是否需要 handoff；交接文件路径>
  【人话】<会不会换人或中断、老板要不要知道，≤2 句>

要求：

- 每个要点后面都写 `【人话】`，并逐条通过 A 的三条判据；缺一不算合格；
- 不写「进展顺利」这类不可判定的句子；
- 不贴完整日志，只给路径与关键行；
- 失败必须写失败命令、退出码和已排除的路径；
- 中途汇报不改变 AC，也不代表验收通过。

## C. 汇报自查

- [ ] 结论可在第一行看到。
- [ ] 每一段都有一句 `【人话】`，且三条判据全过：≤2 句 / 能单独读懂 / 能支撑拍板。
- [ ] 人话没有写成第二篇说明，也没有引入术语表。
- [ ] 每个结论都有证据路径或命令。
- [ ] 失败和取舍没有被隐藏。
- [ ] 没有把工程师自述写成验收结论。
- [ ] 一页纸没有超过约定长度；细节都在链接里。
- [ ] 老板读完后知道下一步做什么。
