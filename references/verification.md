# 独立验收

正式验收由未参与实现的新上下文承担。PM 复跑或工程师自测可以帮助定位问题，但不能代替它。
角色由派发职责及上下文策略确定；子代理、CLI、模型名都不是资格证明。

## 输入与身份

PM 提供需求、约束、AC、基线 BASE、交付 RESULT、独立工作区、允许的测试/环境准备动作。
登记 `role=verifier`、`context_policy=fresh`、PM/工程师/验收 session ID 和被验版本。
不 fork PM，不续实现线程，不带实现聊天、自评或预先结论；同任务修复后的正式复验另开新上下文。

## 工作区和权限

- 独立快照保持源码、测试、锁文件和规格不变。
- 已批准的依赖准备、构建和测试输出可写独立临时目录；不要共享工程师构建缓存。
- 不改验收标准，不用 stash/reset/clean 改造现场，不在交付源码上做临时修复。
- 测试无法运行就写清缺什么；不越权补环境，不把未验证写成通过。

## 验什么

```bash
git status --porcelain
git diff --stat BASE RESULT --
git diff BASE RESULT --
```

工作区 diff 只说明是否被污染。即使工作区干净，也必须检查 BASE 到 RESULT 的实际变更。
在 RESULT 快照亲自重跑 AC 命令。必要的基线对照使用另一份 BASE 快照，不能在交付目录切换或回退。
查范围、删掉的测试、异常处理、凭据及其他阻断级缺陷。建议不凑数量，也不作为失败借口。

## 结论

- PASS：所有必需检查亲自通过，指向准确交付版本；另列残余风险。
- FAIL：有复现的失败、违规或阻断级缺陷，附最小证据。
- BLOCKED/未验证：必需检查没跑成，说明原因；不得写 PASS WITH CAVEAT 冒充全部通过。

只写自己的证据和结论，不改实现。PM 保留原判定，补充事实可以请求澄清，不能自己改成 PASS。
返工回原工程师上下文。正式复验需要新上下文，但不用重复检查没有变化且仍适用的范围。

低风险 direct 工作可以只自检，应报告“自检，未独立验收”，不能显示独立验收员或签独立回执。
